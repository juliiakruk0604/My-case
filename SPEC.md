# РЕЕСТР ДЕЛЬТ — спецификация жанра

Не «кейс». Новый носитель. Все решения ниже — обязательные, агенты не переизобретают их.

## 1. Что отменяем

Классический кейс (Behance / Dribbble / Upwork portfolio / PDF-презентация) имеет 5 свойств.
Каждое — слабость. Мы инвертируем все пять.

| Классический кейс | Реестр дельт |
|---|---|
| Ретроспективен: рассказ о прошлом | Проспективен: датированный прогноз о будущем покупателя |
| Нефальсифицируем: проверить нельзя | Фальсифицируем: прогноз можно признать неверным, и промахи публикуются |
| Про автора: «я сделал» | Про покупателя: считает ЕГО экономику на ЕГО числах |
| Статичен: картинка/текст | Исполняем: инструмент, который вычисляет, а не утверждает |
| В единицах ремесла: экраны, компоненты | В деньгах и времени: €, месяцы, payback |

## 2. Единица носителя — ЛИСТ

Портфолио = не галерея, а финансовый реестр. Один проект = одна строка реестра = один ЛИСТ.
Наверху реестра — одно агрегированное число: суммарная созданная стоимость / суммарный гонорар = мультипликатор.

Обязательные поля ЛИСТА (порядок фиксирован):

1. **ЗАГОЛОВОК-ЧИСЛО.** Одно число с интервалом и метод в одну строку.
   Пример: `€ 214 000 ± 38 000 создано за 11 недель · гонорар € 9 500 · ×22,5 · метод: A/B, n=31 400, 6 недель`
2. **СТАВКА (до работы).** Что было предсказано ДО начала: базовая метрика, предсказанная дельта, срок, условия проигрыша.
3. **ПЕЧАТЬ ВРЕМЕНИ.** Хеш git-коммита, в котором ставка была зафиксирована до старта работ. Прогноз, опубликованный заранее в публичном репозитории, нельзя переписать задним числом. Это не заявление — это проверяемый факт. Ссылка на коммит обязательна.
4. **ИНСТРУМЕНТ.** Живой калькулятор: покупатель вводит свои числа (трафик, конверсия, AOV/ARPU, churn) и видит СВОЙ разрыв и СВОЙ payback. Кейс считает, а не хвалит.
5. **ДЕЛЬТА (после работы).** Замеренный результат: значение до, значение после, n, срок, метод, кто мерил. Каждое число имеет ярлык происхождения (см. §3).
6. **ПРОМАХ.** Обязательное поле. Что предсказано неверно и на сколько. Лист без заполненного промаха считается недействительным.
7. **ЦЕНА СКОРОСТИ.** Часы и € на экран/фичу против отраслевой базы; на сколько недель раньше вышел релиз и сколько это стоило в деньгах.

## 3. Ярлыки происхождения чисел

Каждое число в реестре несёт один ярлык. Смешение запрещено, ярлык не опускается.

- `[ЗАМЕРЕНО]` — инструментальные данные. Обязательны: n, срок, метод, источник данных.
- `[ТЕСТ]` — собственное юзабилити-тестирование. Обязательны: n участников, задача, метрика.
- `[БЕНЧМАРК]` — отраслевой источник. Обязательна ссылка и год.
- `[МОДЕЛЬ]` — расчёт по формуле из чужих вводных. Обязательны формула и допущения.
- `[ПРОГНОЗ]` — ещё не проверено. Обязательна дата разрешения.

Число без ярлыка — брак. Завышенная дельта убивает доверие быстрее, чем её отсутствие:
консервативная оценка с интервалом сильнее красивой цифры без метода.

## 4. ТАБЛО

Сквозная страница поверх всех листов: все ставки, предсказанное против фактического,
доля попаданий, средняя ошибка прогноза. Включая проигранные. Дизайнер с публичным
счётом точности — то, чего в профессии нет.

## 5. Визуальный язык

Запрещено: мокапы в перспективе на подставках, градиентные обложки, «Problem / Process /
Solution / Result», слова «пиксель-перфект», «user-centric», «эстетика», размытые скриншоты,
блоки Lorem-персон, стоковые фото команды у доски.

Ориентир: финансовая выписка, бортжурнал, протокол испытаний. Плотность чисел выше
плотности слов. Моноширинный шрифт для всех величин. Цвет только как носитель смысла
(попадание / промах / прогноз), не как украшение.
