## ШОТ 1 — Empresex · crypto exchange (терминал в покое)

**Title:** `Crypto exchange UI — read as financial infrastructure, not a casino`

**Description:**
```
Product UI for an EU-licensed exchange, where a wrong number costs real money. I dropped the neon-casino look and rebuilt the screens to read like a calm terminal: data rows instead of cards, one warm accent reserved only for live and pending states, nothing decorative competing with the balance.

Design system: warm neutrals on #141414, 5 colours, modest radii.
My part: research, IA, UI, the design system, and the front-end build.
```
**Tags:** fintech, crypto, dashboard, product design, ui, design system, dark ui, web app, saas, data

## ШОТ 2 — Fintech payout dashboard (числа-пруф)

**Title:** `Fintech payout dashboard — settled balance in 1 screen, not 4`

**Description:**
```
A payout product where users kept asking support one thing: “where’s my money?” I rebuilt the information architecture around that one question. Settled balance moved from 4 screens to 1. Support tickets tagged “payout status” dropped 38% in the first month — measured after launch, raw counts in the case.

42 screens · 64-component design system · designed and shipped in Next.js.
```
**Tags:** fintech, dashboard, product design, ux, information architecture, design system, saas, data visualization, web app, ui

## ШОТ 3 — Options strategy builder (before → after)

**Title:** `Options strategy builder — 23 controls on load → 6`

**Description:**
```
A data-heavy fintech screen showed five panels at equal weight, so a first-timer couldn’t tell that the filters drive the table and a table row redraws the chart. I made that order the layout: filters collapse to one line, the ranked strategy table leads, payoff and editor stay quiet until a row is picked.

Controls on first load: 23 → 6. Decisions before a first action: 5 → 1.
Before/after, same product, same task.
```
**Tags:** fintech, dashboard, ux, product design, before after, data visualization, saas, web app, ui, redesign
