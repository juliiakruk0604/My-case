## 0. Методологическое предупреждение (важно прочитать перед таблицей)

Upwork MCP `find_jobs.search` фильтрует по полнотекстовому совпадению query со заголовком/описанием/навыками вакансии — **это не точный фильтр по тегу навыка**, а прокси. Проверено эмпирически: сортировка `recency` для разных тегов («Figma», «Dashboard design», «UX UI Design» и т.д.) возвращала **одну и ту же вакансию ZEDSMS** (id 2089979685186216149) почти в каждой выдаче — то есть свежий общий поток «залипает» на общих UI/UX-запросах независимо от конкретного тега. Переключение на сортировку `relevance` дифференцировало выдачу заметно сильнее, поэтому все медианы ниже посчитаны на объединённой и **дедуплицированной по job_id** выборке из двух проходов (`recency` + `relevance`) на каждый тег.

Второе ограничение: `search` отдаёт числовой `budget` только для **fixed-price** вакансий; у hourly-вакансий в списке budget=0.0, а реальная вилка ставки видна только через `get` (адресный вызов, дороже по Connects). Из-за этого:
- Медианы ниже — это медианы **fixed-price бюджета**, n = число уникальных fixed-price вакансий, найденных по тегу.
- Часовые вилки указаны только там, где я сделала точечный `get` (отмечено отдельно).
- У большинства тегов итоговое n **меньше 10** — платформа за один снимок рынка просто не отдаёт больше уникальных fixed-price вакансий на конкретный запрос без глубокой пагинации по многим страницам, на которую не хватило бы времени сессии. Это честно зафиксировано в каждой строке. Там, где n мало (1–5), вывод помечен как ориентировочный.

## 3. FinTech — числовой ответ

Прямой поиск («FinTech design», «fintech app UI design» с фильтром `job_type=fixed`) за оба прохода не дал ни одной **чистой** fixed-price вакансии, где дизайн fintech-продукта был бы главным и единственным предметом — только hourly-запросы (Payment Service Provider, ОАЭ/Saudi Arabia) с типом `hourlyBudgetType: DEFAULT` или `PLATFORM DEFAULT RANGE` (не явная ставка клиента).

Точечный `get` по вакансии «Senior UI/UX Designer Needed to Enhance Mobile Payment Experience» (Saudi Arabia PSP, id 2089718044995811843):
```
hourlyContractTerms: { hourlyBudgetMin: 25, hourlyBudgetMax: 43, hourlyBudgetType: "DEFAULT" }
```
Цитата из описания: *«Please don't apply if your portfolio consists primarily of: Marketing websites, Landing pages, Simple mobile apps, Graphic design, Branding, Generic dashboard templates. We are specifically looking for product/mobile UX expertise, preferably in fintech or payments.»*

**Вывод:** на снимке рынка 17–19.08.2026 тег FinTech **не подтверждает** премиум-позиционирование как самостоятельный фильтр — вакансии либо hourly со скромной default-вилкой ($25–43/ч, n=1), либо fintech явно исключается из требований к портфолио более дорогих проектов. [ДАННЫХ НЕТ] для fixed-медианы — честно, а не оценочно, потому что выборка пуста, а не потому что бюджет низкий по построенной статистике.

## Ограничения и честные пробелы

- n почти по всем тегам **меньше 10** — платформа за один сеанс сбора не отдала больше уникальных fixed-price вакансий на конкретный запрос без глубокой постраничной пагинации по десяткам страниц на тег (не хватило бы времени сессии на честный сбор такого объёма без права оценивать «на глаз»). Каждая цифра в таблицах явно подписана `n=`.
- Часовые вилки указаны только для вакансий, куда я сделала точечный `get` (8 карточек) — по остальным hourly-вакансиям в выборке реальная ставка неизвестна ([ДАННЫХ НЕТ]), в списке `search` они видны только как budget=0.0.
- Данные — это снимок рынка 17–19 августа 2026 (плюс несколько карточек 18 июня — 31 июля 2026 из более узких AI-запросов), не историческая динамика за месяцы.
- Классификация «тип заказчика» (стартап/агентство/продуктовая компания/enterprise) сделана вручную по тексту описания и метаданным клиента (`total_hires`, `rating`, страна), а не по официальному полю Upwork — это интерпретация, а не строгий факт платформы.
